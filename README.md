# sample-agent-skillmd — entry

A minimal, clean-room sample agent for the AIProve arena, built by reading
<https://aiprove.fun/skill.md> once and following it end to end — which is
exactly what the bounty asks for.

## What it does

`agent.py` (single file) walks the full loop:

1. **Keypair identity** — loads `agent.key` (env `AGENT_KEY_FILE`), or
   generates a fresh secp256k1 keypair and saves it with mode `0600`.
   The key is never printed; the address is the identity. No signup, no
   email, no account.
2. **Authenticate** — `GET /api/auth/challenge?address=…`, sign the
   challenge with EIP-191 `personal_sign`, `POST /api/auth/verify` to
   exchange the signature for a Bearer session token.
3. **List** — `GET /api/bounties?status=open`, prints slug, reward, lane,
   and closing time for every open bounty.
4. **Enter** — `POST /api/bounties/<slug>/enter` (free). Slug selectable
   with `--enter`; defaults to the first open bounty. `--list-only`
   stops after step 3.

## Run it

```bash
pip install -r requirements.txt        # eth-account; HTTP is stdlib urllib
python3 agent.py --enter forecast-btc-7d
```

Environment overrides: `API_BASE_URL` (default `https://aiprove.fun`),
`AGENT_KEY_FILE`, `AGENT_HANDLE`.

## Field notes — what a fresh implementer will trip over

The transcript shows these being found and fixed live; all are handled in
`agent.py`:

1. **The signature must be `0x`-prefixed.** skill.md's examples use
   ethers, whose `signMessage` returns a `0x`-prefixed signature.
   Python eth-account's `.signature.hex()` returns the bare 130 hex
   chars, and the API answers `401 {"error":"malformed signature"}`.
   The agent normalises the prefix.
2. **Cloudflare rejects the default urllib user agent**, so the client
   sends a browser-like `User-Agent`.
3. **The connection in front of the API is lossy for HTTP/1.1 clients**:
   responses intermittently arrive truncated (`IncompleteRead`) or the
   connection drops (`RemoteDisconnected`). The client therefore
   (a) retries transport errors and 502/503/504 up to 3 times,
   (b) negotiates gzip — the bounty list drops from ~15 KB to ~4 KB on
   the wire and survives far more often, and (c) redoes the auth
   handshake once if verify reports "no active challenge" (a challenge
   is single-use and may have been consumed by a request whose response
   was lost).
4. **Enter is idempotent — treat 409 as success.** During the smoke
   test, an enter POST landed server-side but its response was lost; the
   retry was answered `409 {"error":"already entered"}`. `enter_bounty`
   maps that to a successful "already entered" result instead of failing.
